Gemini Omni Flash currently does not accept uploaded audio references. The production path therefore remains:

```text
original track
  → local MIR + Gemini Music Reading
  → time-coded Visual Score and locked ShotSpecs
  → silent/no-music visual generation
  → deterministic edit against the untouched original track
```

This limitation reinforces the product thesis: music-to-film structure must live in our directing layer rather than inside one opaque generation request.

## Video-generation budget policy

The account has a daily limit of ten video generations. One confirmed Gemini video was generated during this Step 0 session; the account-wide remaining count is not assumed because other clients may share the quota.

Every future video request must satisfy all of the following:

1. the visual state and relevant Film Bible invariants are approved;
2. the ShotSpec has musical, narrative, and visual functions;
3. intended time range, camera, action, material transition, lighting, and exclusions are explicit;
4. a complex prompt of at least 600 characters is stored in a file and reviewed;
5. the output is intended to enter the final-cut candidate pool;
6. `--prompt-file` and `--confirm-final-candidate` are supplied to the provider script.

Do not spend calls on provider discovery, short smoke prompts, or cosmetic variants. Use image generation, fixtures, and local editorial previews before motion generation.

## Open-weight route on Modal

The selected direction is LTX-2.3 distilled on Modal rather than local inference.

Why it fits this product:

- the official pipeline exposes audio-to-video conditioning;
- keyframe interpolation maps directly to Visual States;
- retake supports localized repair;
- model code and weights are inspectable and provider-replaceable.

Deployment shape:

| Concern | Decision |
| --- | --- |
| Runtime | Isolated Modal image with Python 3.12 and the model's pinned CUDA/PyTorch stack |
| GPU starting point | H100 or H200; benchmark quality, memory, latency, and cost before choosing |
| Weights | Revision-pinned Hugging Face snapshot in a Modal Volume |
| Load lifecycle | Load once per warm container with `@modal.enter` |
| Invocation | Asynchronous task returning provider job state and immutable output provenance |
| Secrets | Modal Secret for Hugging Face access if required |
| Local hardware | Irrelevant to production inference; local machine has no usable NVIDIA GPU |

The LTX-2 weights use the LTX-2 Community License Agreement rather than a permissive software license. Review it before a commercial launch. For the hackathon, treat this route as open-weight and inspectable—not license-free.

Current Modal state:

- CLI not installed;
- `MODAL_TOKEN_ID`, `MODAL_TOKEN_SECRET`, and `HF_TOKEN` are not present in the repository `.env`;
- no weights were downloaded locally because only about 5 GB disk is free;
- Modal deployment is a later work item and does not block the fixture-first local app.
